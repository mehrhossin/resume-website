مطالعه پروژه / بک‌اند، سرور بازی و کنسول

PlayWinمعماری یکپارچه یک تجربه بازی آنلاین.

زیرساخت بازی آنلاین برای دستگاه‌های فیزیکی آرکید؛ از شناسایی دستگاه و بازیکن تا ورود به لابی، اجرای بازی و ثبت نتیجه.

طراحی و پیاده‌سازی بک‌اند و سرور مرکزی، گیم‌سرور، کنسول Unity و ارتباط بازی‌ها با سرور را انجام داده‌ام؛ با تفکیک مسئولیت میان اقتصاد سامانه و گیم‌پلی لحظه‌ای.

۰۱ / مسئله

یک مسیر هماهنگ، از دستگاه تا نتیجه بازی.

در یک شبکه از دستگاه‌های بازی، ورود بازیکن، یافتن حریف، انتخاب گیم‌سرور و شروع بازی باید با وضعیت مالی و هویت دستگاه هماهنگ باشد. هم‌زمان، پیام‌های حساس به زمانِ گیم‌پلی به مسیر ارتباطی مخصوص خود نیاز دارند.

در PlayWin این جریان میان سه بخش پیاده‌سازی شده است: بک‌اند برای هویت، لابی، اقتصاد و نتیجه؛ سرور Unity برای اجرای بازی و وضعیت روم؛ و کنسول برای تجربه ورود و اجرای بازی روی دستگاه.

۰۲ / نقش و پیاده‌سازی

مسئولیت در هر سه لایه محصول.

BACKEND / ASP.NET CORE 8

بک‌اند و سرور مرکزی

پیاده‌سازی احراز هویت و جداسازی دسترسی دستگاه، بازیکن و ادمین با REST API و JWT؛ اجرای فرمان‌های اقتصادی در بک‌اند و مدیریت لابی، matchmaking و اعلان نتیجه و کیف پول با SignalR؛ ذخیره داده با MySQL و Dapper و مدیریت صف و وضعیت با Redis و Lua.

GAME SERVER / UNITY HEADLESS

گیم‌سرور و ارتباط بازی

پیاده‌سازی سرور Unity Headless، اتصال شبکه‌ای بازی با Mirror و KCP/UDP، چرخه روم و مسابقه، ارتباط داخلی با بک‌اند و ارسال نتیجه بازی؛ همراه با منطق قطع و اتصال مجدد در جریان بازی.

CONSOLE / UNITY

کنسول و اجرای بازی روی دستگاه

پیاده‌سازی ورود دستگاه و بازیکن، ارتباط با لابی و سرور مرکزی، دریافت اطلاعات نشست و راه‌اندازی بازی از طریق GameSession.json؛ سپس اتصال کلاینت بازی به گیم‌سرور تعیین‌شده.

۰۳ / تصمیم‌های معماری

مرز روشن میان گیم‌پلی و مدیریت سامانه.

مرز مشخص میان فرمان و رویداد
احراز هویت و فرمان‌های اقتصادی از طریق REST API و JWT انجام می‌شوند. SignalR مسئول لابی، matchmaking و اعلان نتیجه و تغییرات کیف پول است؛ Mirror KCP/UDP مسیر مستقیم گیم‌پلی میان کلاینت و گیم‌سرور را فراهم می‌کند.
هماهنگی صف و نشست با Redis
صف‌های matchmaking، وضعیت نشست، قفل‌ها و توکن ورود یک‌بارمصرف با Redis و اسکریپت‌های Lua مدیریت می‌شوند؛ اطلاعات ماندگار در MySQL قرار می‌گیرد.
مرجعیت بک‌اند در اقتصاد و نتیجه
تراکنش‌های اقتصادی و ثبت نهایی نتیجه در بک‌اند انجام می‌شوند. گیم‌سرور مسئول وضعیت و اجرای بازی است و نتیجه را از مسیر ارتباط داخلی گزارش می‌کند.
توجه به چرخه اتصال
جریان قطع ارتباط و بازگشت بازیکن، بازیابی وضعیت نشست و هماهنگی کنسول با سرور در طراحی ارتباطات در نظر گرفته و پیاده‌سازی شده است.

۰۴ / جریان اجرا

از ورود بازیکن تا ثبت نتیجه.

  1. ورود و شناساییکنسول، هویت دستگاه و بازیکن را با بک‌اند هماهنگ می‌کند.
  2. لابی و matchmakingصف، نشست و تخصیص گیم‌سرور در لایه مرکزی مدیریت می‌شوند.
  3. اجرای بازیکنسول اطلاعات نشست را به بازی می‌دهد؛ کلاینت از طریق Mirror KCP به سرور Unity متصل می‌شود.
  4. پایان و نتیجهگیم‌سرور نتیجه را گزارش می‌کند؛ بک‌اند ثبت نهایی و رویدادهای مرتبط با اقتصاد و نتیجه را انجام می‌دهد.

۰۵ / فناوری و مستندسازی

یک قرارداد مشترک برای اجزای محصول.

معماری کلی، جریان ارتباطات و قراردادهای API و SignalR برای هماهنگی بک‌اند، گیم‌سرور و کنسول مستند شده‌اند. نمودار تعاملی، همین اجزا و مسیرهای ارتباطی را نمایش می‌دهد؛ نام بازی‌ها، شمار دستگاه‌ها و وضعیت‌ها در آن نمونه‌های توضیحی هستند.

  • ASP.NET Core 8
  • C#
  • MySQL
  • Dapper
  • Redis + Lua
  • SignalR
  • JWT
  • Unity Headless
  • Mirror
  • KCP / UDP
